# 私密影片整理

MoviePilot V2 插件，用于扫描指定目录中的视频文件，识别影片编号，刮削元数据，生成 Emby/Jellyfin 可识别的 `movie.nfo`、`poster.jpg`、`fanart.jpg`，并将视频整理到目标媒体库目录。

适合把不适合走 MoviePilot 常规识别流程的影片单独归档到私有媒体库。

## 主要功能

- 扫描一个或多个来源目录，并按目录映射整理到不同目标目录。
- 等待文件稳定后再处理，避免下载未完成时提前移动。
- 从文件名中识别常见影片编号，例如 `SSIS-123`、`IPX-999`、`FC2-PPV-1234567`、`HEYZO-1234`。
- 根据编号刮削元数据，生成 `movie.nfo`。
- 下载封面图；封面下载失败时使用 ffmpeg 截图生成 `poster.jpg` 和 `fanart.jpg`。
- 支持未识别文件保底整理，避免文件长期滞留。
- 支持移动、复制、软链接、硬链接。
- 使用 SQLite 记录处理状态和历史，避免同一文件版本重复处理。
- 可选同步 MoviePilot 整理记录，并触发媒体库刷新事件。

## 配置示例

### 目录映射

每行一组映射，格式为：

```text
来源目录:目标目录
```

示例：

```text
/downloads/private:/media/私享影库/日韩
/downloads/manual-private:/media/私享影库/其他地区
```

如果只写来源目录，不写目标目录，插件会把目标目录视为同一路径。

### 常用配置

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| 启用插件 | 关闭 | 开启后按扫描周期自动执行 |
| 立即运行一次 | 关闭 | 保存配置后立刻执行一轮扫描 |
| 扫描周期 | 10 分钟 | 自动扫描间隔 |
| 识别失败目录 | `/media/未识别影片` | 未识别编号时的保底归档目录 |
| 排除关键字 | 内置 qB 临时目录等 | 路径包含这些关键字时跳过 |
| 文件稳定等待 | 30 秒 | 文件入队后先等待一段时间 |
| 稳定检测间隔 | 30 秒 | 两次稳定检测之间的间隔 |
| 稳定命中次数 | 2 次 | 连续 size 和 mtime 不变后才处理 |
| 截图位置 | `10%` | 生成封面截图时的视频位置 |
| 刮削源 | `site_a` | 当前实现中 `site_a` 等同 javdb 网页解析 |
| 刮削失败策略 | 保底整理 | 可选择保底、跳过或下轮重试 |
| 目标已存在策略 | 跳过 | 可选择跳过、覆盖或自动追加后缀 |
| 整理方式 | 移动 | 支持 move、copy、softlink、hardlink |
| 状态数据库 | `/config/plugins/javorganizer/state.sqlite` | SQLite 状态和历史记录路径 |

## 实现逻辑

插件入口是 `plugin.py`，负责读取 MoviePilot 配置、启动定时线程、暴露 API 和插件命令。真正的扫描与整理流程在 `scanner.py` 的 `JavOrganizerProcessor` 中执行，并且同一时间只允许一轮任务运行。

一轮任务分为三个阶段：

1. 扫描阶段  
   插件遍历配置的来源目录，筛选视频扩展名文件，跳过排除关键字命中的路径，并通过 SQLite 判断同一路径、大小、mtime 的文件版本是否已经成功处理过。符合条件的文件会进入本轮候选列表。

2. 稳定检测阶段  
   候选文件先等待 `stable_wait_seconds`，之后按 `stable_check_interval_seconds` 周期读取 size 和 mtime。连续 `stable_check_count` 次不变才视为稳定文件。文件消失会标记为 `missing`，异常会记录日志并跳过。

3. 处理阶段  
   对稳定文件逐个处理。插件先从文件名提取影片编号；识别成功后调用刮削器获取标题、演员、标签、发行日期、封面等信息；识别失败则进入保底整理。最终会创建目标目录、写入 `movie.nfo`、生成或下载图片，并按配置移动、复制或链接视频文件。

处理成功后，插件会写入历史记录。如果开启媒体库刷新，会在本轮有成功入库时广播刷新事件；如果 MoviePilot 整理记录同步可用，也会把结果同步到 MoviePilot 的整理历史中。

## 编号识别

编号识别逻辑在 `parser.py` 中：

- 先把文件名转为大写。
- 去除分辨率、编码、字幕、括号内容等噪声。
- 匹配 `FC2-PPV-数字`、`HEYZO-数字`、`字母前缀-数字` 等格式。
- 忽略 `H264`、`H265`、`X264`、`AAC`、`HEVC` 等容易误判为编号的前缀。

示例：

```text
[ABC] SSIS-123-C 1080p.mp4
```

会被识别为：

```text
SSIS-123
```

## 输出结构

识别成功时，默认按影片编号创建目录：

```text
/media/私享影库/日韩/SSIS-123/
├── SSIS-123.mp4
├── movie.nfo
├── poster.jpg
└── fanart.jpg
```

未识别编号时，会进入保底目录。开启“重命名未识别文件”后，目录名和文件名会使用时间戳，减少重名冲突：

```text
/media/未识别影片/20260527_213000/
├── 20260527_213000.mp4
├── movie.nfo
├── poster.jpg
└── fanart.jpg
```

## 元数据与图片

刮削逻辑在 `scraper.py` 中。当前实现通过 javdb 搜索编号，再解析详情页中的标题、演员、标签、发行日期、时长和封面地址。

图片处理策略：

- 优先下载刮削结果中的封面图。
- 下载失败或没有图片地址时，使用 ffmpeg 从视频中截图。
- `movie.nfo` 会写入标题、编号、标签、演员、片长、视频宽高、编码、原始路径和来源地址等信息。

截图和视频信息依赖 `ffmpeg` / `ffprobe`。如果运行环境没有这些命令，插件仍可整理文件和写入基础 NFO，但截图和部分视频信息会缺失。

## 状态与重复处理

插件使用 SQLite 保存两个表：

- `files`：记录文件路径、大小、mtime、状态、编号、错误和重试次数。
- `history`：记录每次成功归档的来源路径、目标路径、状态、编号和时间。

重复处理判断基于：

```text
path + size + mtime
```

同一个文件版本成功处理后，后续扫描会跳过；如果文件内容变化，大小或 mtime 改变，则会按新版本重新进入流程。

## 触发方式

- 插件配置页开启后，按扫描周期自动运行。
- 勾选“立即运行一次”后，保存配置会启动一次后台扫描。
- 插件命令 `/video_archive` 可触发立即扫描。
- 插件 API 提供扫描、状态、历史和清空历史接口。

## 注意事项

- 建议来源目录只配置下载完成或即将完成的目录，不要直接扫描整个媒体库根目录。
- 排除关键字应覆盖 qBittorrent 临时目录、回收站、缓存目录等。
- 默认整理方式是移动；如果还需要继续保种，请改用硬链接或复制，并确保来源和目标所在文件系统支持对应方式。
- 保底整理会让未识别影片也进入媒体库，建议单独配置一个私有库并控制用户权限。
- 刮削源是网页解析，可能受目标站点可用性、网络代理和页面结构变化影响。
